## Sobre

Gosto de recriar coisas do zero para entender como funcionam. Meu foco hoje é C# e .NET: back-end, motores de negociação e integrações financeiras, sempre com testes cobrindo as regras. Também mantenho um sistema de tesouraria em Java com Spring Boot e uma coleção de jogos em JavaScript puro, sem framework e sem build.

- CondePlay: um serviço de streaming inteiro em seis repositórios e cinco linguagens
- Back-end em C# e .NET 8: APIs, workers, event sourcing, SignalR, EF Core e benchmarks
- Java 21: ledger de partidas dobradas com Spring Boot, gerador de bytecode, árvore B+ em disco, cliente HTTP e motor de regex
- Node puro, sem dependência nenhuma: WebSocket, objetos do Git, tar, JWT, DNS, JSON, empacotador e log append-only
- Jogos clássicos em HTML5 Canvas, um repositório por jogo
- Projetos pequenos e frequentes, cada um com CI e testes

## CondePlay, um serviço de streaming em seis partes

Catálogo, player, tela, metadados, recomendação e telemetria. Cada parte é um
repositório, e juntas são as cinco linguagens do perfil. O conteúdo é inventado
para o projeto e as mídias apontam para fluxos HLS públicos de teste. Não há um
arquivo de vídeo nem uma imagem de terceiros em lugar nenhum.

| | Parte | Stack | Destaques |
|---|-------|-------|-----------|
| 🎬 | [Catálogo](https://github.com/condeDeveloper/catalogo) | C# 12 · .NET 8 · EF Core · SQLite · xUnit | a API: filmes e séries com CRUD, temporadas, episódios, perfis, minha lista, avaliações e progresso. Paginação por cursor opaco em vez de `OFFSET`, que repete e pula itens quando o catálogo muda entre duas páginas. O SQLite não ordena `DateTimeOffset`, e sem o conversor binário doze rotas devolviam 500. 54 testes |
| 📺 | [Player HLS](https://github.com/condeDeveloper/player-hls) | JavaScript · Media Source Extensions · node:test | player HLS sem `hls.js`: playlist mestra e de mídia, fila de buffer, qualidade adaptativa e recuperação de erro. O estimador de banda descarta amostras de menos de 50 ms, porque um segmento servido pelo cache em 5 ms diz 92 Mbps e não mediu rede nenhuma. Sobe com 30% de folga e desce na hora. 61 testes |
| 🍿 | [CondePlay](https://condedeveloper.github.io/conde-play/) | JavaScript · HTML · CSS · node:test | a tela: perfis, herói, fileiras, ficha com temporadas, busca, minha lista e o reprodutor. Sem framework, sem build, sem dependência. Nenhum arquivo de imagem no repositório: cada capa é um SVG gerado do nome e de uma cor tirada do id. Cai para o catálogo embutido quando a API não está no ar. 34 testes |
| 🎞️ | [MP4](https://github.com/condeDeveloper/mp4) | Node puro · node:test | leitor de metadados de MP4: árvore de caixas, duração, resolução e cadeia de codec da RFC 6381. O `avc1.64001f` montado a partir de três bytes do arquivo é o mesmo que a Mux e a Apple escrevem no `CODECS=` das playlists delas. O formato tem três escalas de tempo ao mesmo tempo, e usar a errada dá 250 segundos para um vídeo de 5. 90 testes |
| 🧮 | [Recomendações](https://github.com/condeDeveloper/recomendacoes) | Python puro · unittest | o "porque você assistiu X": filtragem colaborativa item-item, semelhança por conteúdo e a mistura das duas. | 📡 | [Eventos de Reprodução](https://github.com/condeDeveloper/eventos-de-reproducao) | Java 21 · JUnit 5 | a telemetria que alimenta os dois anteriores, a partir de eventos que chegam repetidos e fora de ordem. Cem embaralhamentos de uma semana de eventos, com um em cada cinco duplicado, têm de chegar ao mesmo estado da entrega perfeita. Foi esse teste que achou o bug de guardar "concluído" como estado pegajoso. 46 testes |
